# 浩然音乐项目说明书

## 1. 系统定位

浩然音乐把音乐目录、播放体验、社区关系、创作者工作流、数字商品和个性化推荐放在同一套身份、审核、支付和媒体资产体系中。系统既支持单机开发，也提供三节点数据与媒体环境的管理脚本。

## 2. 系统组成

浏览器端负责界面、播放控制、即时校验和本机文件选择；Spring Boot 后端负责身份、授权、业务状态、事务、配额和审计；MySQL 保存事实数据，Redis 提供短期状态与保护能力，Kafka/WebSocket承担异步和实时投递；搜索默认由 MySQL 完成，并可显式启用 Elasticsearch 索引适配与故障回退；Nginx 统一入口；Hadoop/Hive/Spark 承担离线分析与推荐训练；本地音乐服务只处理用户明确授权的本机目录。

## 3. 主要使用流程

用户注册登录后可发现和播放音乐，收藏歌曲、维护歌单、参与评论与广场、关注其他用户并接收通知。创作者可建立草稿、上传媒体并提交审核；审核通过后，内容或商品进入对应目录。购买流程由后端重新确认商品、金额和权益，支付完成后以幂等方式发放；商品撤下时按策略区分目录隐藏与已购权益保留。

“我的收藏”以歌曲、专辑、MV 和歌单四类视图展示，并允许建立最多 20 个账号级收藏分组，完成命名、改名、前后排序、筛选、归组和撤出。每件收藏同时只属于一个分组；移除分组不会取消收藏。歌曲使用与歌单详情一致的信息行，版本和语种相邻展示，播放量不进入该页面；其他资源的整理、分享和取消收藏使用带中文提示的图标操作。

处理结果复核分为账号限制、创作者登记和作品处理三类，关联对象均由服务端依据当前身份和真实记录确认。用户来信分为功能异常、功能建议、内容纠错、显示与无障碍、服务投诉和订单退款；退款只能关联本人订单，普通来信不能改变订单或权益。

表情包上传先在浏览器本地预览，用户确认后才发送到服务器。后端登记上传批次、核对所有权和额度、校验图片并写入托管目录；完成后创建表情记录。审核通过时才接入商店目录和可购买状态。取消本地选择不会产生服务器草稿；已上传草稿删除由服务端核对状态与引用并清理文件。

## 4. 安全与可靠性

所有浏览器输入都视为不可信。按钮是否可见、页面步骤和前端函数不能决定权限；服务端对直接请求、重放、篡改、并发和跳步分别校验。上传使用大小/格式/内容检测、速率、日配额、并发槽、幂等批次和恢复清理。支付、审核、权益和通知使用事务、业务键、条件更新和补偿。日志采用稳定事件字段并避免敏感数据。

## 5. 数据与模型

当前数据库结构由 190 张基础表、9 个视图、4 个触发器、5 个函数、5 个存储过程和 4 个事件组成，交付结构脚本不含业务数据。推荐训练对播放与收藏交互去重过滤，生成带版本和哈希清单的模型；发布前验证，发布后做健康检查，失败恢复上一版本。在线模型不可用时降级到内容或热度结果。

## 6. 部署与维护

开发环境分别构建后端、前端和本地音乐服务。集群环境从 node1 按依赖顺序控制组件。配置先形成节点化副本，秘密由运行环境注入；发布执行预检、备份、暂存、校验、原子替换和回滚。详细命令与版本见《软件与配置要求》和《集群部署与运维》。

## 7. 交付边界

交付内容是源码、测试或约定的源码子集、运维与训练脚本、现行结构 SQL、脱敏配置和项目文档。运行所需真实密码、私钥、业务数据、媒体文件、依赖和构建产物需要由部署环境另行提供。
